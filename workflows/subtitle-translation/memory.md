# 记忆文件约定

翻译是跨块有状态的过程。四个记忆文件承载状态,位于工作区,人类可审阅、可续跑。

## 文件与格式

| 文件 | 内容 | 格式 | 上限 |
|------|------|------|------|
| `term_consistency_table.txt` | 正片专有名词 → 稳定译文 | 每行 `key<TAB>value` | 无硬上限,建议 ≤ 200 条 |
| `meta_translation_rules.txt` | 可复用元翻译规则(语境/口吻/单位/货币等) | 每行 `key<TAB>value` | ≤ 120 条,单条 ≤ 300 字 |
| `synopsis_memory.txt` | 前情提要:仅正片主线的单段中文 | 单段文本 | ≤ 12000 字 |
| `ad_memory.txt` | 已识别的广告概括 | 每行一条 1~2 句中文 | 建议 ≤ 100 条 |

> 格式沿用旧项目约定。若某个值不含 TAB 也可写 `key => value` 或自然短句,但要保持文件内自洽、人类可读。

## 更新时机与规则

- **每次翻译块完成后**检查四个文件是否需要更新,更新后写入文件(覆盖写,保持全量最新状态)。
- `term_consistency_table.txt`:
  - 新增/修改:`key<TAB>value` 行(重复 key 覆盖)。
  - 删除:直接删行。
  - 只收录正片专名;**广告口播、优惠码、导流链接、三连号召等内容严禁写入**。
- `meta_translation_rules.txt`:同术语表;规则必须可跨块复用,不得写本轮临时碎片(如"第 5 块语气要愤怒"之类的一次性信息)。
- `synopsis_memory.txt`:每块更新后如果主线有推进,重写整段;写错即覆盖,不存在追加。
- `ad_memory.txt`:每检测到一段广告,追加一行概括(与已有行重复则不追加)。概括须覆盖:品牌/产品、推广话术要点。

## 广告判定(与 prompts/ad-policy.md 一致)

口播推广(赞助感谢、注册领奖、优惠码、置顶链接、导流注册、关注三连、专属折扣等)一律视为广告段:
- 广告段**必须翻译**,不得漏译,不得跳过。
- 广告信息**不得**进入术语表、元规则、前情提要;只进 ad_memory.txt。
- 若一段广告内容与广告策略无关但在术语上撞车(如正片提到某公司),按正片处理,正常入术语表。

## 记忆文件的读取

- 翻译每块时,把四个文件的内容作为上下文注入(参考 prompts/translate-module.md)。
- 文件不存在或为空视为"尚无",不报错。

## 一致性要求

- 术语一致性是质量门槛之一(见 quality.md 翻译自检清单第 2 条):发现同一专名译文漂移,立即回改已翻块并统一术语表。
- 记忆文件的最终状态会交付用户审阅(quality.md 交付清单第 4 项)。
